# Phase 12 Report: Daily Ranking, No-Trade Analytics and Alerts

Date: 2026-09-26 · Status: complete, all checks green

## Implemented
- **Daily ranking** (`app/ranking/service.py`):
  - Every stock in the universe (one listing per company) gets the same **standardised candidate**:
    - entry at the last close known at `as_of`;
    - stop at entry − max(2 × ATR(14), 3% of entry);
    - target at entry + 2.5 × the stop distance;
    - size from the paper portfolio's risk budget, capped by the maximum order value.
  - The candidate is evaluated by the **real 24-gate Trade Risk Engine**. Nothing is proposed, stored as a decision, or ordered.
  - A stock is **QUALIFIED** only if every **opportunity** gate passes.
  - **Operational** gates are reported separately, as blockers of *orders* rather than of opportunity quality:
    - kill switch, execution mode, portfolio match;
    - the spread gate, which needs a live quote at order time.
  - Rows are ranked: qualified first, then expected net return, then composite score. Unknown values sort last.
  - When nothing qualifies, the headline says **`NO QUALIFIED OPPORTUNITIES TODAY`**. A stock without enough history is reported as blocked by `data`, and no levels are invented for it.
  - **Point in time:**
    - Levels and gates use only data available at `as_of`.
    - With `refresh_reports`, stale reports are regenerated **first**. The evaluation instant then moves to after the refresh, so every new report exists before the gates read it (`created_at ≤ as_of`).
    - Fixed while finishing the phase: before this, a report refreshed during a ranking was invisible to the engine.
  - Each run is stored in `ranking_runs` and is **immutable** (trigger). It records the rows, a histogram of first blocking gates, the operational blockers and the config fingerprint. Every run is audited.
- **Counterfactuals:** for every past ranking, the realised forward return and the excess over NIFTY 50, grouped by QUALIFIED / `blocked:<first gate>`.
  - Entry is the next session's close; exit is `horizon` sessions later, the same convention as the backtest labels.
  - Candidates still inside their window are counted as *pending*.
  - This shows whether the gates reject the right trades.
- **Alerts** (`app/alerts/service.py`, table `alerts`):
  - Always stored in-app, **once per dedupe key**. A concurrent duplicate is caught by the unique constraint in a savepoint.
  - The alert is **stored first, then pushed**, so a duplicate is never pushed twice.
  - It goes to Telegram and/or email when it meets `min_severity_to_push` (default `warning`).
  - A channel failure is recorded per channel (`failed: <ExceptionClass>`) and never loses the alert. Tokens and URLs are never written into the delivery record.
  - Sources:
    - | Source | Severity |
      |---|---|
      | Ranking result | info, or warning if something qualifies |
      | Thesis `STOP_HIT` | **critical** |
      | Thesis `TARGET_HIT`, `HORIZON_EXPIRED`, `STANCE_DETERIORATED` | warning |
      | Kill switch activated | critical |
      | Kill switch released | warning (from the service, so the API and every other path are covered) |
      | Failed ingestions in the EOD price, news, fundamentals and macro jobs | warning; one per job per day, listing the failed items |
- **Scheduler:** a `daily-ranking` Celery task at 12:30 UTC (18:00 IST), after `paper-eod`.
- **API:**
  - `POST /ranking/run` (admin), `GET /ranking/latest`, `GET /ranking/history`, `GET /ranking/counterfactuals`.
  - `GET /alerts` (with the unread count), `POST /alerts/{id}/read`, `POST /alerts/read-all` (audited), `GET /alerts/channels`.
- **UI:**
  - A new **Ranking** page: headline, operational-blocker banner, ranked table, "why not?" histogram of first blocking gates, counterfactual table and history. The run button is admin-only.
  - An **alerts bell** with an unread count in the navigation.
  - An **Alerts** page with severity badges (icon + word + color), delivery status per channel, and mark read / mark all read.
- Migration 0012: `ranking_runs` (immutable, indexed on `as_of`, foreign key to `portfolios`) and `alerts`.
- Housekeeping: ruff formatting for the autogenerated migration 0011.

## Tests
10 new tests plus a new assertion in the paper-monitor test; 325 in total (1 optional-NLP skip), plus ruff and mypy all clean.
- **Standardised levels are point in time:**
  - The entry is the close known at the ranking date, not the latest one.
  - The stop and target match an independent ATR (the `ta` library) over the same window.
  - A research-mode ranking gives `NO QUALIFIED OPPORTUNITIES TODAY` with an info alert.
  - `execution_mode` is an operational blocker, not the counted failure.
  - The ranking row can't be UPDATEd.
- Insufficient history is reported as `data`, with no levels.
- **Operational vs opportunity gates:**
  - In paper mode with a positive report and a calibrated model, the candidate qualifies, sized from the risk budget.
  - The missing live spread is not a failure.
  - No proposal, decision or order is created.
  - With the kill switch pulled, the stock is still qualified but `kill_switch` appears as an operational blocker.
  - The latest and history endpoints return the right runs.
- **Refresh then evaluate:** a missing report is regenerated at `as_of`, the evaluation happens after it, and the new report is visible to the gates. A fresh report is not regenerated.
- **Counterfactuals:** the forward return and the excess over NIFTY are recomputed independently from the seeded series. A recent ranking counts as pending.
- **Alerts:**
  - Dedupe: no second store and no second push.
  - Info alerts are below the push threshold.
  - An unknown severity is refused.
  - The Telegram payload and URL go through an httpx `MockTransport`.
  - A 502 response and a raising channel are both recorded while the alert is kept, and the bot token never appears in stored data.
- Ingestion-failure alerts: one per job per day.
- Kill-switch activation (critical) and release (warning) alerts; read, unread-only, read-all and 404.
- A thesis `STOP_HIT` raises exactly one critical alert that says a human must still approve.
- Every endpoint requires authentication; running a ranking requires admin.

## Live status
Not re-run on real market data in this session. In the sandbox configuration (research mode, unlicensed Yahoo prices, no active model) every stock is blocked (`data_licensed` first), so the expected daily headline is `NO QUALIFIED OPPORTUNITIES TODAY`.

## Limitations
- The ranking evaluates one standardised plan per stock; it does not search over entries, stops or horizons.
- Counterfactuals use split-adjusted closes and do not deduct costs; they are diagnostics, not a performance claim.
- Alert read state is shared by all users (single-desk deployment).
